## Abstract

Sync committee aggregators are currently self-selected, so each member signs a
`SyncAggregatorSelectionData` under `DOMAIN_SYNC_COMMITTEE_SELECTION_PROOF` and
aggregates if the hash of that signature falls below a threshold.

This EIP replaces the VRF-like lottery with `get_sync_aggregator_pubkeys`,
a pure function of beacon state, and removes the selection proof from `ContributionAndProof`.

The main feature that we lose is lookahead aggregator privacy, however we don't
have this for includers and proposers; roles that actually affect consensus.

## Motivation

Secrecy of the aggregator set until publication, is the main property that
the current BLS signature contribution proof is giving us.

Using BLS however means two things:

- Post-quantum transition: BLS signatures are not PQ safe.

- Attributable non-performance: A validator that lost the lottery is today
indistinguishable from one that won and stayed silent, so aggregation duty cannot
be monitored or penalised (if we wanted to do this)

The more important aspect here is post quantum and we solve this by having a
determinstic selection since that does not require key material.

### New constants

| Name | Value |
| - | - |
| `DOMAIN_SYNC_COMMITTEE_AGGREGATOR` | `DomainType('0x12000000')` |

### New `get_sync_aggregator_pubkeys`

```python
def get_sync_aggregator_pubkeys(state: BeaconState,
                                slot: Slot,
                                subcommittee_index: uint64) -> Sequence[BLSPubkey]:
    """
    Return the aggregator pubkeys for ``subcommittee_index`` at ``slot``.
    """
    seed = hash(
        get_seed(state, compute_epoch_at_slot(slot), DOMAIN_SYNC_COMMITTEE_AGGREGATOR)
        + uint_to_bytes(slot)
        + uint_to_bytes(subcommittee_index)
    )
    subcommittee = get_sync_subcommittee_pubkeys(state, subcommittee_index)
    return [
        subcommittee[compute_shuffled_index(uint64(i), uint64(len(subcommittee)), seed)]
        for i in range(TARGET_AGGREGATORS_PER_SYNC_SUBCOMMITTEE)
    ]
```

- The seed MUST be derived via `get_seed` as shown, not from
`get_randao_mix(state, get_current_epoch(state))`.

- `get_sync_subcommittee_pubkeys` is unchanged, including its rule for resolving
`current_sync_committee` against `next_sync_committee` at a period boundary.

- Simialr to today, aggregating is based on honest validator behaviour rather than a
consensus obligation, so there is no penalty for an aggregator that
stays silent.

### Modified `is_sync_committee_aggregator`

```python
def is_sync_committee_aggregator(state: BeaconState,
                                 slot: Slot,
                                 subcommittee_index: uint64,
                                 pubkey: BLSPubkey) -> bool:
    return pubkey in get_sync_aggregator_pubkeys(state, slot, subcommittee_index)
```

### Modified `ContributionAndProof`

```python
class ContributionAndProof(Container):
    aggregator_index: ValidatorIndex
    contribution: SyncCommitteeContribution
```

### Modified gossip validation

On the `sync_committee_contribution_and_proof` topic, the condition that verified
`selection_proof` as a signature over `SyncAggregatorSelectionData` is removed,
and we have:

- `[REJECT]` `is_sync_committee_aggregator(state, contribution.slot,
  contribution.subcommittee_index, aggregator_pubkey)`, where `aggregator_pubkey`
  is `state.validators[contribution_and_proof.aggregator_index].pubkey`.

### Removed

- `DOMAIN_SYNC_COMMITTEE_SELECTION_PROOF`
- `SyncAggregatorSelectionData`
- `get_sync_committee_selection_proof`
- the `selection_proof` field of `ContributionAndProof`

`TARGET_AGGREGATORS_PER_SYNC_SUBCOMMITTEE` is retained, with its meaning changed
from an expected count to an exact count (so its no longer bimodal).
